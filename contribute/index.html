Where to help

  
Seven things the game needs.

  
Each one opens a list of small, clear pieces. Pick one, say so in a comment, and go. You don't need to be a developer: plenty of these need a marketer's eye, a sketch or an idea.

  

    

      
Play it and tell us if it works No codeEasiest way in
Play a desk with fresh eyes and say where you got stuck. Help us check that what players learn holds up on a real job.
A good first piece: Playtest a desk for 30 minutes

    

      
Make the desks feel great Needed most
Sitting down at a desk should feel like part of the game. Layout, flow and what goes where on each screen.
A good first piece: Pop-up, full screen, or something else?

    

      
Make the lessons teach better Great for marketers
Clear steps, varied practice, nothing assumed. So a player can do the real job after.
A good first piece: List what a desk assumes you know

    

      
Turn practice into play
Borrow from any game you love. Build a small game mode that still teaches the real skill.

    

      
Art and each desk's theme
Frank thinks he's a detective. The other desks need a character and a look too.
A good first piece: Pitch a theme for the test board

    

      
Shape the story No code
Who are these people, and how does the work change them? Brainstorm only.
A good first piece: Pick a character, sketch their arc

    

      
Smooth the rough edges Small first fixes
Hard-to-read text, screens that break on a phone, slow loading.
A good first piece: Check every screen on your phone

For builders

  
Everything you need to send a change.

  

    

      
Run it on your computer

      
Nothing to install, no build step. You need Python 3 or any static web server.

      
git clone https://github.com/YOUR-NAME/lifecycle-practice
cd lifecycle-practice
python3 -m http.server 8000

      
Then open http://localhost:8000 and reload to see each change.

    

    

      
Building with an AI agent

      
Tell your agent to read AGENTS.md before it touches anything. It covers where everything lives, the rules below, what to test, and what to put in the pull request, review links included.

      
# paste into Claude Code, Codex or Cursor
Read AGENTS.md, then help me build one change.

    

    

      
Review links

      
A review link is a full web address that opens the game right at the thing you changed, so the reviewer clicks once and is there. Put one in every pull request, written out in full. They use a separate practice save, so they never touch anyone's progress. Try these:

      

        An office lessonhttps://lifecycle-practice.vercel.app/office/?dev&try=data:where→
        A Lifecycle Files stephttps://lifecycle-practice.vercel.app/lifecycle-files/?start=step&step=2s3&profile=office-dev→
        A Test Board stephttps://lifecycle-practice.vercel.app/test-board/?embed=U2a&save=office-dev→
      

    

  






  
House rules

  
Six rules every change follows.

  
They're why the game teaches well. More detail in CONTRIBUTING.md.

  

    
01One new thing per stepTeach one idea, practise it alone, then join it with what came before.

    
02Every screen asks for a callNo screens that are only reading. The player decides something every time.

    
03Looks like the real toolsKeep the tools' layouts, so practice carries straight over to work.

    
04Made-up everythingMade-up numbers, people and stores. No real company's data.

    
05Nothing to sign up forNo AI calls, no accounts. The game runs entirely in the browser.

    
06Plain wordsShort sentences. Say what to do, not how clever it is.
